# START — desktop-football 缘起

GoalHUD 的 HUDPanel 做出来之后，我反复盯着那个会躲避鼠标的半透明面板看了很久。

整个物理系统——CVDisplayLink 驱动的 60fps 循环、鼠标排斥力场（静力 + 动力）、边界碰撞反弹、拖拽释放——都已经在那里了。它是一套完整的桌面粒子引擎，功能齐全、跑得顺滑，却只用来"躲一下鼠标"。

这不就像造了一台法拉利，然后只用来倒垃圾吗？

## 核心冲动

把那个物理引擎的潜力释放出来。不是再加一个面板，不是再优化躲避算法，而是给它一个新的身体：**一个足球**。

桌面足球的念头一出来就停不下来。思路非常清晰：

1. **重力就是一行代码。** 积分器已经写好了：`vel = vel * decay + force * dt`。加一个 `gravity = (0, -980)`，球就会往下掉。
2. **踢球就是现有的排斥力反着用。** 鼠标快速划过时施加脉冲力，逻辑和 `dynamicK * approachSpeed` 一模一样，只是方向反过来。
3. **边界碰撞已经有。** wall bounce + restitution 已经在 HUDPanel 里跑了好几个版本了，搬过来就行。
4. **停止是摩擦力。** 地面摩擦 + 空气阻力让球最终停下来，参数游戏而已。

换句话说，**Phase 1 就是把 HUDPanel 的面板改成圆形，把排斥力改成踢球力，加上重力**。一两天的事。

## 但我不想只做一个能动的球

我想要的是一个能让人"忍不住玩两分钟"的东西。它需要有：

- **运动真实感**：纹理旋转和线速度严格对应，球滚向左边时逆时针转，被踢飞时加速转。滚动的方向一眼就能看出来——视觉上的"运动感"是核心。
- **3D 透视暗示**：阴影随高度变化（飞起时阴影远离球体 + blur 增大），Y 轴位置缩放（屏幕上方微微变大，模拟远处），弹跳时的 squash & stretch。
- **鼠标交互的层次**：不只是"划过踢飞"，还有接近时的气流感应、点击拍球、长按抓住然后抛出。
- **声音**：踢球声、弹跳声、滚动声。声音带来的沉浸感远超视觉，这件事我做过太多次了，不能省。

## 动画方案的选择

视频和 APNG 第一轮就被淘汰了——它们不能根据物理状态实时改变旋转角度，这是致命的。

Spine 我也认真想了。它在做角色动画时是无敌的，但足球就是个圆球 + 旋转，引入骨骼运行时 overkill。

SpriteKit 是最自然的答案。它自带物理引擎、粒子系统、sprite atlas 支持——而且 `SKScene` 可以嵌入 `NSView`，放到 `NSPanel.contentView` 里就是桌面挂件了。macOS 上这么做是经过验证的（Desktop Goose、各种屏保），性能方面 `ignoresSiblingOrder = true` + `shouldCullNonVisibleNodes` 应该能打。

Core Animation 作为轻量备选——Phase 1 用纯 CALayer 验证手感的时候就用它。

## Mission Control 的问题

四指上滑时，WindowServer 会对所有窗口做 scale-down transform，这个行为无法阻止。

但我不想和系统对着干。球缩小一下反而很有意思——像是"被吸进 Mission Control"。真正的透视效果不应该靠窗口级缩放，而是靠足球自身的渲染：阴影的 offset/blur 随高度变化、Y 轴缩放暗示、Z 轴旋转。

## 和 GoalHUD 的关系

这不是 GoalHUD 的子功能。足球是一个独立的桌面挂件，有自己的窗口、自己的物理循环、自己的交互逻辑。它们可以同时运行，互不干涉。

唯一共用的东西是：物理引擎的思想、NSPanel 的窗口配置模式、以及"轻量桌面存在感"的设计哲学。
